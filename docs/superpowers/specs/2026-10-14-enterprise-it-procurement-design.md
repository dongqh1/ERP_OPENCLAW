# 企业 IT 设备采购方向设计

## 目标
在现有采购助手决策能力旁新增企业 IT 设备采购目录和评估链路，支持按设备类别、硬件规格、操作系统、预算、交付期限和保修期筛选报价。

## 方案
保留现有 LangGraph、DeepAgents、MCP、FastAPI、MongoDB Checkpointer、OpenSandbox 和订单审批链路。新增 IT 设备目录查询 API 与 MCP Tool，并保留独立的 IT 设备确定性策略函数与 LangChain Tool，由采购分析 Agent 调用。订单继续使用 ERP 的 `part_id` 和既有订单接口，沿用审批中断与恢复机制。

IT 演示数据采用单独的 `IT-DEMO-*` 供应商/物料编码，并把 CPU、内存、存储、操作系统、保修和预计交期天数放在新增的 IT 规格扩展表中。IT 物料映射到既有 `part` 与 `supplier` 表，使其可经原订单链路下单；查询结果标注“本地演示目录（模拟数据）”，不冒充市场实时报价。初始化采用幂等插入，只新增或更新带 IT 演示前缀的记录。

一次评估针对同一设备类别及数量。需求规格可包含最低 CPU 核数、内存、存储、允许的操作系统和最低保修期。评估器使用 Decimal 计算总价，并对型号类别、规格、预算、交期和保修逐项判定；不满足硬约束的报价标为不符合，缺少关键数据的报价标为待核实。只有全部约束通过且报价有来源时才生成推荐，排序优先总价较低、保修期较长、交付较早。

## 数据与安全边界
不更改现有摩托车零部件的表结构、初始化、记录、查询和订单行为；新 Java 代码只增设 IT 查询端点、规格扩展表和幂等演示数据。IT 数据是明确标记的本地模拟目录，不代表真实供应商报价、可供数量或市场价格；库存字段表示 ERP 账面库存，不得解释成供应商可供量。缺少证据的字段不能由模型推断。设备订单继续使用已核验的 ERP 物料 ID，并通过现有 Human-in-the-Loop 审批。

## 集成与交互
主 Agent 将 IT 设备采购分析委派给 procurement-analyst；分析 Agent 使用新增的 IT 目录工具，订单 Agent 在创建订单前再次核验 ERP 物料。工具配置和采购分析技能明确列出字段来源、约束校验和未知信息处理。订单 Agent 保留原有创建/修改审批。聊天空状态保留研发项目与 IT 入口，并补回摩托车零部件示例入口；README 说明三类入口和模拟数据边界。

## 验证
本次修改按用户要求不新增或运行测试；交付前检查改动清单与差异，确认原摩托车初始化与原有接口实现未被修改。Java ERP、MongoDB、模型及 OpenSandbox 的运行联调需在用户启动项目后进行。
