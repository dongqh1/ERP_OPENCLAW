# 企业 IT 设备采购方向设计

## 目标
在现有研发项目采购决策能力旁新增企业 IT 设备采购评估，支持按设备类别、硬件规格、操作系统、预算、交付期限和保修期筛选带来源的报价。

## 方案
保留现有 LangGraph、DeepAgents、MCP、FastAPI、MongoDB Checkpointer、OpenSandbox 和订单审批链路。新增独立的 IT 设备确定性策略函数与 LangChain Tool，由采购分析 Agent 调用；ERP 查询仍复用已有供应商、物料、库存、历史订单和订单接口。

一次评估针对同一设备类别及数量。需求规格可包含最低 CPU 核数、内存、存储、允许的操作系统和最低保修期。评估器使用 Decimal 计算总价，并对型号类别、规格、预算、交期和保修逐项判定；不满足硬约束的报价标为不符合，缺少关键数据的报价标为待核实。只有全部约束通过且报价有来源时才生成推荐，排序优先总价较低、保修期较长、交付较早。

## 数据与安全边界
不改造或假设 Java ERP 新增接口，不造 IT 产品目录、供应商、报价、库存、交期或保修信息。可用信息必须来自现有 ERP 查询、可追溯的供应商资料或用户确认。未维护 IT 设备条目的 ERP 需要先录入真实目录数据；缺失字段不能由模型推断。设备订单继续使用已核验的 ERP 物料 ID，并通过现有 Human-in-the-Loop 审批。

## 集成与交互
主 Agent 将 IT 设备采购分析委派给 procurement-analyst；其工具配置和采购分析技能明确列出字段来源、约束校验和未知信息处理。订单 Agent 保留原有创建/修改审批。聊天空状态展示项目采购与 IT 设备采购两个方向，并提供 IT 采购示例入口；README 说明能力和数据前置条件。

## 验证
纯策略层用无外部服务依赖的 pytest 单元测试覆盖可执行推荐、缺失数据待核实、规格/预算/交期/保修不符合及确定性排序。子 Agent 配置加载测试验证工具绑定；Python 编译检查和前端测试/构建验证集成。外部 ERP、MongoDB、模型及 OpenSandbox 联调不在离线自动测试范围内。
