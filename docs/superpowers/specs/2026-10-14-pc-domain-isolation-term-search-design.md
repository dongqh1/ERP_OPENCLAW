# PC 领域会话隔离与按需术语查询设计

## 目标

修正汽车/PC 会话切换时可能沿用旧领域的问题；为 PC Agent 增加一个仅在陌生术语影响配置判断时调用的网络解释工具，并避免重复搜索和把长网页内容塞进上下文。

## 领域隔离

继续采用一条会话固定一个领域。前端切换领域时创建新会话；后端收到与会话元数据冲突的领域参数时返回明确提示，不静默改用另一个 Agent。汽车与 PC 各自使用独立 Agent 图和 MCP 工具；FastAPI、前端、Router 与 MongoDB 部署可共享。这样不会把汽车对话历史交给 PC Agent，也不会让 PC Agent 调用汽车 ERP 工具。

## 术语查询

PC MCP 增加 `pc_term_lookup(term)`，复用项目现有的 Sogou Web Search API。PC Agent 在识别不了的名称会影响用途判断或选件时才调用；不为已知术语、每轮对话或价格/库存查询搜索。搜索词只包含待解释术语，不附带完整用户消息；最多返回 3 段、总计约 1200 字的摘要；同一归一化术语在 MCP 进程内缓存 24 小时，最多缓存 128 个术语。

查询结果交给当前 PC Agent 根据上下文判断该名称属于游戏、软件、硬件或工作负载，不额外调用第二个 LLM。搜索失败时返回可读状态，Agent 应说明无法确认并向用户追问，不能编造分类。该工具注册在 PC MCP，不进入汽车 Agent 工具池。

## 验收范围

确认后端对领域不匹配请求有清晰反馈；确认 PC MCP 暴露五个工具且术语搜索结果有长度限制和缓存；确认 Agent 提示词说明按需调用；做 Python 编译和服务工具发现检查。当前约束下不新增或运行自动化测试。

## 不在本次范围

不修改电脑配置优化规则、硬件目录、汽车 Agent 的搜索逻辑、图表能力或真实电商数据源。
